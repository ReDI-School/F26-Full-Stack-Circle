the basics

JavaScript that tells you about mistakes before you run it

Why?

A bug JavaScript doesn't see


// cart.js
function getTotal(price, quantity) {
  return price * quantity;
}

getTotal(10, 2);      // 20 ✅
getTotal('10', 2);    // 20 😅 (lucky)
getTotal(10);         // NaN 😱

JavaScript runs it anyway

No warning. You find the bug later, in the browser, or a user finds it for you.

TypeScript stops you here

It checks your code while you type, and underlines the mistake in red in VS Code.

What is it?

TypeScript = JavaScript + types

📜

JavaScript


function getTotal(price, quantity) {
  return price * quantity;
}

A variable can hold anything, and change later.

+
🔷

TypeScript


function getTotal(price: number, quantity: number) {
  return price * quantity;
}

We say what each value is. Files end in .ts / .tsx.

Every JavaScript you know is still valid. TypeScript only adds the : type parts, and they are removed before the code runs.

What you'll see

Errors show up in your editor


getTotal('10', 2);
Argument of type 'string' is not assignable to parameter of type 'number'. 

getTotal(10);
Expected 2 arguments, but got 1.

Read the message slowly: it says what you gave and what was expected. pnpm typecheck shows every error in the project at once.

The type goes after the name, with a colon: name: type.

Good news

You don't have to write every type


let title = 'Wooden chair';
// TypeScript already knows: string

title = 42;
Type 'number' is not assignable to type 'string'.

This is called inference

TypeScript guesses the type from the value. Hover a variable in VS Code to see it.

Rule of thumb: write types for function parameters and for objects you describe. Let TypeScript figure out the rest.

Functions

Typing a function


//                       parameters           return type
function formatPrice(price: number, currency: string): string {
  return `${price.toFixed(2)} ${currency}`;
}

formatPrice(25, '€');  // "25.00 €"

// the same thing as an arrow function
const formatPrice2 = (price: number, currency: string): string => {
  return `${price.toFixed(2)} ${currency}`;
};

// nothing to return? use void
function logItem(title: string): void {
  console.log(title);
}

The return type is optional — TypeScript can infer it — but writing it makes the intent clear.

Objects

Describing the shape of an object


let item: { title: string; price: number; isSold: boolean } = {
  title: 'Wooden chair',
  price: 25,
  isSold: false,
};

item.price = 'cheap';
Type 'string' is not assignable to type 'number'.

It works… but imagine writing { title: string; price: number; isSold: boolean } every time you need an item. 😩 Let's give the shape a name.

Naming a shape, option 1

type


type Item = {
  title: string;
  price: number;
  isSold: boolean;
};

const chair: Item = {
  title: 'Wooden chair',
  price: 25,
  isSold: false,
};

function markAsSold(item: Item): Item {
  return { ...item, isSold: true };
}

Write it once, use it everywhere

type Name = … gives a name to any type.

Naming

Types start with a capital letter: Item, User, ButtonProps.

Naming a shape, option 2

interface

type


type Item = {
  title: string;
  price: number;
  isSold: boolean;
};

interface


interface Item {
  title: string;
  price: number;
  isSold: boolean;
}

For objects, they do almost the same job. Notice: interface has no =.

Simple rule: use interface for object shapes (like component props), and type for everything else (like unions, coming up next).

Properties

Optional ? and readonly


interface User {
  readonly id: number;   // can't be changed
  email: string;
  name?: string;         // may be missing
}

const ana: User = { id: 1, email: 'ana@redi.org' };  // ✅ no name

ana.id = 2;       // ❌ read-only
ana.name.length;  // ❌ name might be undefined

name?

The property is optional. Its type becomes string | undefined.

readonly

You can read it, but not change it after the object is created.

'ana.name' is possibly 'undefined'.

"This or that"

Union types |


// a value can be one type OR another
let id: string | number;
id = 42;      // ✅
id = 'a42';   // ✅

// even better: a list of exact values
type Condition = 'new' | 'like-new' | 'good' | 'used';

let condition: Condition = 'good';   // ✅
condition = 'broken';                // ❌

Literal types

Only these exact strings are allowed. No typos possible!

Bonus: autocomplete

Type ' in VS Code and it suggests the allowed values.

Type '"broken"' is not assignable to type 'Condition'.

Using a union

Check first, then use it


function greet(name?: string): string {
  // here, name is: string | undefined
  if (!name) {
    return 'Hello, stranger!';
  }

  // here, TypeScript knows name is a string ✅
  return `Hello, ${name.toUpperCase()}!`;
}

function showId(id: string | number) {
  if (typeof id === 'number') {
    return id.toFixed(0);     // number here
  }
  return id.toUpperCase();    // string here
}

This is called narrowing

After an if check, TypeScript knows more about the value.

Reusing shapes

extends: build on another interface


interface Item {
  id: number;
  title: string;
  price: number;
}

// everything in Item, plus more
interface ClothingItem extends Item {
  size: 'S' | 'M' | 'L';
}

const jacket: ClothingItem = {
  id: 7,
  title: 'Denim jacket',
  price: 30,
  size: 'M',
};

"Is a … with extra"

A ClothingItem is an Item, with a size on top.

No copy-paste

Change Item once, and ClothingItem gets the change too.

You can extend more than one:
interface A extends B, C {}

Reusing shapes

The same idea with type: &

interface → extends


interface ClothingItem extends Item {
  size: 'S' | 'M' | 'L';
}

type → & ("and")


type ClothingItem = Item & {
  size: 'S' | 'M' | 'L';
};

Where you'll see this most

Typing React component props


interface PriceTagProps {
  price: number;
  currency?: string;
  variant: 'normal' | 'sale';
}

function PriceTag({ price, currency = '€', variant }: PriceTagProps) {
  return (
    <span className={variant}>
      {price} {currency}
    </span>
  );
}

// using it
<PriceTag price={25} variant="sale" />     // ✅
<PriceTag price="25" variant="cheap" />   // ❌ ❌

Props = an interface

Name it ComponentNameProps. It documents how to use the component.

Free help

Forget a required prop, pass the wrong type or misspell a variant — TypeScript tells you right away.

Watch out

🚫 Avoid any


let data: any = 'hello';

data.toFixed(2);   // no error… 💥 crashes at runtime
data.whatever();   // no error… 💥

any turns TypeScript off

For that value, you're back to plain JavaScript — and its bugs.

Instead

Write the real type. Don't know it yet? Use unknown: TypeScript makes you check before using it.

A red squiggle is TypeScript helping you, not blocking you. Fix the cause — don't silence it with any or // @ts-ignore. Stuck? Ask for help!
